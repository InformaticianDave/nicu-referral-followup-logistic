# nicu-referral-followup-logistic

Bootstrapped multivariable logistic regression pipeline for predicting
two discharge outcomes in a NICU population:

- **`Referred_vs_NotReferred`** — whether an infant was referred to
  outpatient developmental/coordination services at discharge.
- **`Followup_vs_LTFU`** — whether a referred infant successfully
  attended follow-up versus was lost to follow-up (LTFU).

Predictors are organized into three domains, each modeled and reported
separately:

| Group | Examples |
|---|---|
| `clinical_continuous` | gestational age, birth weight, length of stay, age at discharge |
| `clinical_categorical` | inborn/outborn status, singleton/multiple, discharge disposition, PMD-in-system, WC Connect, visit modality |
| `sociodemographic` | insurance type, interpreter need, maternal/paternal race & ethnicity, Child Opportunity Index (COI), parental education/employment |

This repository contains **no patient data**. `data/synthetic/` holds a
fabricated fixture with the same column names and types as the real
extract, generated by `scripts/make_synthetic_data.py`, used only to
exercise the pipeline end-to-end and in the test suite.

## Why bootstrapped logistic regression

Classical logistic regression reports Wald-test p-values and confidence
intervals that assume large samples and approximately normal sampling
distributions for the coefficients. NICU discharge cohorts are modest in
size, class-imbalanced (few LTFU events relative to successful
follow-ups), and have categorical predictors with sparse cells (e.g. a
handful of infants in a given race/ethnicity × insurance combination).
Under those conditions the classical normal approximation can be
unreliable.

The pipeline instead re-fits the model on `n_boot` (default 200) random
resamples of the training data, and reports:

- **Effect / Odds Ratio** — `exp(coefficient)` from the model fit on the
  full training set.
- **95% CI (Lower/Upper)** — the 2.5th/97.5th percentile of the
  bootstrap distribution of the odds ratio (percentile method), rather
  than a normal-theory interval.
- **P-value (Bootstrap)** — twice the smaller of the proportion of
  bootstrap odds ratios on each side of 1, capturing how often the
  resampled estimate disagrees in sign/direction with "no effect",
  without assuming normality.

This produces intervals and p-values that reflect the actual shape of
the resampled data rather than an idealized distribution, at the cost of
extra compute (one model fit per bootstrap resample).

## Layout

```
src/referral_followup/   core Python package (bootstrap fitting, reporting, ROC)
legacy_R/                 original R/caret exploration scripts (kept for history — see CHANGELOG)
config/variable_groups.yml  predictor → group / reference-category mapping
scripts/make_synthetic_data.py   fabricates data/synthetic/referral_followup_synthetic.csv
scripts/run_analysis.py   end-to-end: both outcomes x three variable groups -> outputs/tables
tests/                    pytest suite
docs/                      variable dictionary, methods write-up, de-identification policy
```

## Quickstart

```bash
pip install -r requirements.txt
python scripts/make_synthetic_data.py
python scripts/run_analysis.py
```

Markdown result tables land in `outputs/tables/`, ROC curves in
`outputs/figures/`. Both are gitignored — they're generated artifacts,
not source.

## De-identification

See `docs/de-identification.md`. In short: no MRNs, names, service
dates, or free-text fields are ever read into this pipeline — only the
coded categorical/continuous predictor and outcome columns listed in
`config/variable_groups.yml`. `scripts/phi_scan.py` runs in CI and
blocks any commit that introduces an identifier-shaped column or an
uncommitted raw-extract filename pattern.
