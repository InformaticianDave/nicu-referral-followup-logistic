# De-identification policy

This repository contains **no protected health information**. The
pipeline reads only the coded predictor/outcome columns listed in
`config/variable_groups.yml` -- never names, MRNs, exact dates of
service, free-text notes, or geographic detail finer than the
categories already present in the extract (e.g. `mat_birthplace` is
US / Non-US, not a city or ZIP).

Guardrails:

1. **Nothing raw is ever committed.** `.gitignore` blocks filenames
   matching extract/export/MRN/`vernov` patterns, and `data-raw/` is
   never populated in version control (see `data-raw/README.md`).
2. **`scripts/phi_scan.py`** statically checks filenames and the
   header row of every data/code file for identifier-shaped names
   (MRN, DOB, SSN, address, phone, patient name) and fails CI if one
   is found. An inline `# phi-scan-ok` marker can exempt a specific
   line a reviewer has confirmed is safe (e.g. a variable literally
   named "mrn" inside a comment explaining that MRNs are not used).
3. **`data/synthetic/`** is the only data ever checked in. It's
   generated by `scripts/make_synthetic_data.py` from independent
   random distributions with a small amount of engineered signal --
   no row corresponds to a real infant, and subject IDs are
   sequential synthetic keys (`SYN0001`, ...), never MRNs.
4. **Dates become durations.** Where the real extract has calendar
   dates, this pipeline only ever consumes derived day-counts
   (`Length_of_stay`, `ageatdc`, ...), already computed upstream of
   this repository -- no date-of-service field is read here.

Run the scanner manually with:

```bash
python scripts/phi_scan.py
```

It also runs in CI (`.github/workflows/ci.yml`) on every push.
